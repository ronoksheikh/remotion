How it renders

  1. VoiceEach slide gets its own clip from ElevenLabs eleven_v4, with timing for every character. ffmpeg speeds it up to 1.1× without changing pitch. Clips are cached, so re-renders cost no credits.
  2. CuesA spoken phrase is linked to a CSS selector. When that word is said, a cursor glides to the element and a yellow spotlight highlights it.
  3. SyncSlide animations are time-warped so each step happens on its word, then holds until the next one.
  4. FramesHeadless Chromium (Playwright) steps the GSAP timeline 60 times per second and takes a screenshot each time. This gives exact frames with no screen-recording lag.
  5. Encodeffmpeg combines each slide's frames with its voice clip, then joins the slides into one MP4 at 1080p60, H.264 with AAC audio.
  6. Share copyA smaller copy (CRF 25) is made to fit the chat upload limit.

Run it

npm install
cp .env.example .env              # add ELEVENLABS_API_KEY
node build.mjs lessons/<lesson> --plan     # voice + cue check
node build.mjs lessons/<lesson> --preview  # fast draft
./run-module.sh <lesson> <lesson> ...      # final MP4s

Fonts and GSAP are stored in vendor/, so rendering works offline.
